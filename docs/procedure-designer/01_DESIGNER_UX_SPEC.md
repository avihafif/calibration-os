# 01 — Visual Procedure Designer: UX specification

Prototype: `design/procedure-designer-prototype/` · screenshots: `screenshots/01-…`, `02-…`.

## 1. Model: tree, not free graph
The workflow is a **structured, bounded block tree** (ADR-0006, *Proposed* — treated as a working assumption, flagged in the register). Lifecycle lanes: **Setup → phases (As-found) → Teardown → Safe state**. Containers: `foreach` (body), `if` (then/else), `repeat_until` (body), `try` (body/handler/finally). "Connecting" steps means placing them in a lane/slot and ordering them; there are no arbitrary edges. Limits (prototype): 120 steps, depth 6.

The **canvas** and the **outline** are two renderings of one view-model (`viewModel()`); every operation is available in both.

## 2. Layout
Three panes (palette · workflow · inspector) plus a bottom **dock**; below 1180 px the inspector drops under the workflow; below 800 px one pane at a time with a pane switcher. Workspaces (top tabs): Procedure · Command Builder · Metrology · Safety · Simulation Lab.

## 3. Adding and moving steps — one command path
Pointer drop, palette Enter/click, the add menu (Insert or `+`), presets, keyboard moves and the outline all call the same `insertNode / moveNode` guarded by `canPlace`. Refusals are explained (lane rules, depth, count, hazardous step in `finally`, only *safe* operations or non-waiting steps in the safe state, no moving a container into itself).

| Action | Pointer | Keyboard |
|---|---|---|
| Add | drag palette item to a drop zone, `+` | Enter on palette item (after selected step), Insert / `+` on a step → searchable menu |
| Select | click | Enter / Space |
| Move focus | — | ↑ ↓ (roving tabindex) |
| Reorder / nest | drag | Alt+↑↓ reorder, Alt+←→ out/into container (mirrored in RTL) |
| Remove / duplicate | — | Delete (toast + undo) / Ctrl+D |
| Breakpoint | — | B |
| Undo / redo | buttons | Ctrl+Z / Ctrl+Y |

Every structural change is announced through an `aria-live` region.

## 4. Inspector (schema-driven)
Generated by the Phase 1A generic renderer from each step's schema + `x-calos-editor` hints; tabs: Settings · Errors · Recovery · Safety & permissions · Notes. Widgets registered for this feature (not per-step screens): `expression` (live validity), `select-from` (roles/ops/tables), `op-args` (typed arguments generated from the chosen named operation), `duration` (quantity or Input required), `error-policy`, `resume-policy`, `bound`, `integer`. Unknown widgets render a visible placeholder (never silent).

Rules surfaced in the UI: retry disabled for H2+/non-repeatable steps; resume policy cannot be weaker than the derived minimum; step bound can only narrow the envelope; hazard, coverage and effective limit are shown **derived, read-only**.

## 5. Dock
Validation (counts by severity and stage, filter, jump to step/field, links to Metrology/Safety) · Hazard path · Recovery matrix · Versions & compare (id-aware diff: added/removed/changed/moved, change class, suggested version; optional overlay on the canvas) · Review & publish.

## 6. Review workflow (proposal)
Draft → In review → Approved → Published (Test registry only). Submit needs 0 errors; approver ≠ submitter; safety-affecting changes need the Safety Officer too; publishing needs the Quality Manager role; **Production release is shown as blocked** (simulation-only/synthetic content). Reasons are required; confirmations show the digest. Simulation evidence is displayed as information, **not** a gate (no policy invented). Persona permissions are a UX demonstration — real enforcement is server-side.

## 7. States covered
Empty slot/lane, no selection, read-only (persona or frozen version), validation errors/warnings/info, blocked drop, undo toast, Hebrew/English, light/dark, touch (larger targets, always-visible `+`).
