## 3. Usability checklist (moderated sessions; extends phase1/10 §8)

### 3.1 Per-persona task scripts (no click paths shown to participants)
| Persona | Tasks | Observe |
|---|---|---|
| Calibration Engineer | T-E1 create a manufacturer and a model with one function (leave ranges as inputs required); T-E2 resolve all validation findings; T-E3 create an application with the wizard; T-E4 submit for review | Does the participant understand *Input required*? Do they look for a "default value"? Do they find *+ New* in the picker? Do required-field errors feel calm? |
| Metrology Approver | T-A1 review a submitted change; T-A2 approve; T-A3 try to approve own change | Do they find the Review summary and Compare? Do they understand why approval is blocked? Do they read the digest? |
| Quality Manager | T-Q1 publish an approved change; T-Q2 pick the version number; T-Q3 find who approved and when; T-Q4 withdraw an item that is in use | Do they understand *change class*/*minimum version*? Do they trust "synthetic"? Can they find history? |
| Lab Manager | T-M1 find what is waiting and for whom; T-M2 see whether anything blocks release | Is *Next step* sufficient? Do they miss aging/waiting-since? |
| Platform Administrator | T-P1 find the deployment identity; T-P2 confirm they cannot approve; T-P3 find the role matrix | Do they expect to see content? (D-30) |
| Calibration Technician | T-T1 "where do I start a calibration?" | Landing message adequate? (Operator shell is not in this prototype) |

### 3.2 Observation guide (record, do not score against thresholds)
Task success (unaided / with hint / failed) · time on task · wrong turns · hesitations at: Input required, inclusivity, review/approve distinction, version bump · verbatims for each synthetic-versus-real confusion · any participant who believes data is saved or an approval is real (**safety-of-understanding signal; escalate immediately**) · assistive-technology participants flagged.

### 3.3 Language and direction
Run each task once in English and once in Hebrew (RTL) by native speakers; note terminology that feels wrong (feeds MI-31), mixed-direction rendering faults, truncated Hebrew, and any place where an English term leaks into the Hebrew UI.

## 4. Additional acceptance criteria (extend phase1/13 §5)

| ID | Criterion | Type |
|---|---|---|
| P1A-AC-53 | Required-field errors are painted inline only after the field is visited or Validate/Submit is attempted; readiness counts and the drawer always include them (S-03). | E |
| P1A-AC-54 | Reference pickers offer an inline **+ New** that returns to the same field with the new item selected and does not navigate (S-02). | E |
| P1A-AC-55 | Entering values on an *Input required* quantity prefills the first unit of the chosen quantity; invalid decimal text yields the decimal-rule message (not a generic oneOf message) (S-04). | E, U |
| P1A-AC-56 | `pattern` findings append the field's `pattern_help` text. | U |
| P1A-AC-57 | Approvers see a **Review summary** (changes, class, one-click to Compare with versions preselected) on in-review items they are eligible to approve. | E |
| P1A-AC-58 | The publish flow has at most three steps and always shows pinned dependencies and the content digest before confirmation. | E |
| P1A-AC-59 | First publication is classified *Initial version* (min 1.0.0), never *Metrological*. | U |
| P1A-AC-60 | Actions a role lacks permission for are shown disabled **with a reason** (tooltip and screen-reader text) on dashboards, lists and editors; the control is never silently removed inside a visible screen. | E |
| P1A-AC-61 | Form-level undo/redo uses Ctrl/Cmd Z / Shift Z outside text inputs; inside text inputs native text undo is untouched; toolbar buttons always work. | E |
| P1A-AC-62 | The creation wizard's steps, fields and initial values come from `wizard_step`/`initial` hints and the registry `wizard` flag; no wizard code names a kind. | U |
| P1A-AC-63 | Natural-language values in diff/data cells use `dir=auto`; identifiers, keys, hashes, versions, paths and codes are LTR-isolated and monospaced. | E |
| P1A-AC-64 | `DigestText` (short form, full on hover/focus, copy) is used everywhere a digest is displayed. | U, E |

## 5. Definition of done — per screen (use in every Phase 1A PR)
- [ ] Route, regions and states match [02](02_BUILDER_UX_SPEC.md); loading, empty, filtered-empty, error, read-only, offline, forbidden implemented or explicitly N/A.
- [ ] All text via ICU keys (en + he, `needs_review` flagged); no literal strings; pseudo-locales clean.
- [ ] Logical CSS only; RTL screenshot approved; identifiers/values LTR-isolated.
- [ ] Keyboard-only walkthrough recorded; focus order, focus return, skip link, live regions.
- [ ] axe: 0 critical/serious (en, he, light, dark); contrast tokens test green.
- [ ] Disabled-with-reason everywhere permissions/governance block an action.
- [ ] Findings painted by pointer with codes; drawer; *Go to field*.
- [ ] No kind-specific code in renderer/designers (lint); new widgets/hints reviewed and tested.
- [ ] Synthetic-mode guardrails verified: banner, persona chip, no storage/network, production-bundle exclusion.
- [ ] Capability Matrix rows updated; traceability tags (`@req`) present.
